# Ubuntu 构建、运行和可视化

以下命令使用新的副本。需要 x86-64、AVX2 CPU。Windows 生成的 build_float32 不能直接用于 Ubuntu；这里另用 build_ubuntu_float32。

## 1. 准备目录与依赖

若使用 WSL Ubuntu，可直接复制已有两个目录到 Linux 文件系统：

```bash
export TASK_BASE="$HOME/motion_planning"
mkdir -p "$TASK_BASE"
cp -a /mnt/d/codex_talk/project_1/project_code/RRTstarDFPFF_paper_r2_float32_strict_20261007 "$TASK_BASE/"
cp -a /mnt/d/codex_talk/project_1/project_code/dynobench-main "$TASK_BASE/"
```

原生 Ubuntu 请先把新副本和已使用的 dynobench-main 文件夹拷贝到上述 TASK_BASE，再从下面继续。必须保持 dynobench-main/dynobench-main/envs 的实际嵌套层级，或相应修改 TASK_DYNO。

```bash
export TASK_BASE="$HOME/motion_planning"
export TASK_PROJECT="$TASK_BASE/RRTstarDFPFF_paper_r2_float32_strict_20261007"
export TASK_DYNO="$TASK_BASE/dynobench-main/dynobench-main"
cd "$TASK_PROJECT"

sudo apt update
sudo apt install -y build-essential cmake ninja-build libeigen3-dev libyaml-cpp-dev python3-venv python3-pip

python3 -c "from pathlib import Path; assert 'avx2' in Path('/proc/cpuinfo').read_text(), 'AVX2 required'; print('AVX2 available')"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-viewer.txt

cmake -S . -B build_ubuntu_float32 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON \
  -DRRTSTARDFPFF_ENABLE_AVX2=ON
cmake --build build_ubuntu_float32 --parallel 2
ctest --test-dir build_ubuntu_float32 --output-on-failure
python -m unittest discover -s tests -p test_run_six.py -v
```

DynoBench 只需要原始 YAML 及 Python viewer 源码，不需要编译 DynoBench/FCL。

## 2. 六个场景的短时检查与官方可视化

```bash
export TASK_CPU="$(python -c 'import os; print(min(os.sched_getaffinity(0)))')"
export TASK_SMOKE="$TASK_PROJECT/results/ubuntu_smoke_$(date +%Y%m%d_%H%M%S)"

python tools/run_six.py \
  --dynobench-source "$TASK_DYNO" \
  --build-dir build_ubuntu_float32 \
  --protocol latency --runs 1 --timeout 3 --seed 41 --cpu "$TASK_CPU" \
  --shortcut true --shortcut-mode flask --shortcut-time original_duration \
  --output "$TASK_SMOKE"

MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_SMOKE" --dynobench-source "$TASK_DYNO" \
  --mode dynobench --trajectory final --skip-failed \
  --output "$TASK_SMOKE/figures_official"

xdg-open "$TASK_SMOKE/figures_official/index.html"
```

若有失败，run_six 返回 2，summary.csv 保留失败；继续执行绘图命令可显示成功场景。
没有成功轨迹时不会生成伪造结果。没有桌面浏览器可直接打开 PNG 或把结果目录复制到 Windows 查看。

## 3. 正式 latency：20 seeds，首解立即退出

```bash
export TASK_LATENCY="$TASK_PROJECT/results/latency_20_$(date +%Y%m%d_%H%M%S)"
python tools/run_six.py \
  --dynobench-source "$TASK_DYNO" --build-dir build_ubuntu_float32 \
  --protocol latency --runs 20 --timeout 120 --seed 41 --cpu "$TASK_CPU" \
  --shortcut true --shortcut-mode flask --shortcut-time original_duration \
  --output "$TASK_LATENCY"

MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_LATENCY" --dynobench-source "$TASK_DYNO" \
  --run 0 --mode dynobench --trajectory raw --skip-failed \
  --output "$TASK_LATENCY/figures_raw_seed41"
MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_LATENCY" --dynobench-source "$TASK_DYNO" \
  --run 0 --mode dynobench --trajectory shortcut --skip-failed \
  --output "$TASK_LATENCY/figures_shortcut_seed41"
xdg-open "$TASK_LATENCY/figures_shortcut_seed41/index.html"
```

seeds 为 41..60；`--run 0` 对应 seed 41，`--run 19` 对应 seed 60。
RAW planning latency 看 search_time / first_solution_time；包含 Algorithm 4 的时间看 total_time=search_time+shortcut_time。

## 4. 正式 anytime：20 seeds，每个 120 s

```bash
export TASK_ANYTIME="$TASK_PROJECT/results/anytime_20_$(date +%Y%m%d_%H%M%S)"
python tools/run_six.py \
  --dynobench-source "$TASK_DYNO" --build-dir build_ubuntu_float32 \
  --protocol anytime --runs 20 --timeout 120 --seed 41 --cpu "$TASK_CPU" \
  --shortcut true --shortcut-mode flask --shortcut-time original_duration \
  --output "$TASK_ANYTIME"

MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_ANYTIME" --dynobench-source "$TASK_DYNO" \
  --run 0 --mode dynobench --trajectory final --skip-failed \
  --output "$TASK_ANYTIME/figures_final_seed41"
xdg-open "$TASK_ANYTIME/figures_final_seed41/index.html"
```

六个问题的 anytime 主搜索预算总计约 4 小时，另有初始化、后处理和输出时间。manifest 会记录实际 affinity、构建和输入哈希。
不要把不同机器或构建的 latency 数据直接混合。

## 5. 可视化调试与消融

```bash
MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_SMOKE" --mode checker_geometry --trajectory raw --skip-failed \
  --output "$TASK_SMOKE/figures_checker"
MPLBACKEND=Agg python plot_successful_results_paper.py \
  --experiment "$TASK_SMOKE" --mode trajectory_only --trajectory first --skip-failed \
  --output "$TASK_SMOKE/figures_first_only"
```

shortcut 关闭：运行命令中用 `--shortcut false`。
增强版：用 `--shortcut-mode cost_decreasing --shortcut-time optimal`。
只跑单场景：追加 `--cases uni_bugtrap` 等。
legacy r2 对照：追加 `--numeric-profile legacy_mixed`，此模式不执行新 shortcut。
高阶对照：追加 `--df-mode full_df`，自动采用 legacy_mixed；不能与 float32_production 同用。

每次使用新的 output 名称，脚本拒绝覆盖已有结果。
姿态/omega 的起终点和连接误差在 boundary_diagnostics_*.csv 中，r=2 保持 diagnostic-only。
本机验证在 Windows 完成；以上 Ubuntu 命令尚未在 Ubuntu 主机执行。
